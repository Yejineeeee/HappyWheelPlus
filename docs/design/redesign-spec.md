# HappyWheel+ 리디자인 설계 문서

- 작성일: 2026-11-05
- 상태: 사용자 검토 대기
- 목적: 2025–26 동계 해외문화탐방(8조) 프로젝트로 만든 휠체어 여행 웹앱을 **GIS/데이터 분석 직무 포트폴리오**로 다시 만든다.

---

## 1. 배경과 목표

### 1.1 지금 상태 (원본 저장소)
- `index.html` + `app.js`(991줄 한 파일) + `styles.css`, MapLibre 지도, OSM 타일.
- 흐름: 나라 → 도시 → 코스 → 지도 → 길안내. 4개국 9개 도시, 도시당 코스 1~2개(코드에 직접 적혀 있음).
- 문제점
  - 길찾기(OpenRouteService)·AI 기능을 쓰려면 사용자가 **API 키를 직접 입력**해야 함 → 면접관이 링크를 열면 대부분 기능이 안 보임.
  - 하단 탭으로 빈 화면에 바로 갈 수 있음.
  - 내장 편의시설 데이터가 도시당 1개.
  - `manifest.webmanifest`가 비어 있고 서비스워커는 껍데기만 있음.
  - 휠체어 접근성을 실제로 "분석"하는 부분이 없음(코스 난이도는 손으로 적은 값).

### 1.2 목표
1. 링크만 열면 **키 입력 없이 모든 핵심 기능이 동작**한다.
2. GIS 역량을 보여준다: **접근성 점수 모델**, **재현 가능한 데이터 파이프라인**, **도시 간 비교 대시보드**.
3. 원래 프로젝트의 정체성(휠체어 사용자를 위한 유럽 여행 코스 앱)을 유지하고 완성도를 높인다.

### 1.3 범위에서 뺀 것
- 현장 평가(발표 자료의 난이도/별점)와 계산 점수의 통계적 비교 검증: 원자료가 없고 코스 수가 적어 의미 있는 검증이 어렵다. 현장 평가는 **참고 배지로만** 표시하고, 노트북에서 간단한 일치 여부만 언급한다.
- 9개 외 도시 추가, 다국어 UI(화면은 한국어만, README만 한/영).
- 사용자 계정, 서버 DB.

## 2. 전체 구조

```
HappyWheelPlus/
├─ pipeline/            # Python 데이터 수집·분석
│  ├─ config/cities.yaml
│  ├─ src/happywheel/   # 수집, 경사 계산, 점수, 경로, 내보내기
│  ├─ notebooks/methodology.ipynb
│  └─ tests/
├─ web/                 # 사용자가 보는 웹앱 (Vite + TypeScript)
│  ├─ public/data/      # 파이프라인 결과물 (저장소에 커밋)
│  ├─ src/
│  └─ tests/
├─ worker/              # AI 중계 서버 (Cloudflare Worker, TypeScript)
├─ docs/
└─ .github/workflows/   # 테스트 + GitHub Pages 배포
```

- 파이프라인은 개인 PC에서 가끔 실행하고, 결과 파일을 `web/public/data/`에 저장해 커밋한다. 배포는 파이프라인 실행과 무관하다.
- 비용: GitHub Pages·Cloudflare Worker·지도 타일·고도 데이터 모두 무료. 유료는 OpenAI 호출뿐이며 사용량 상한으로 통제한다.
- 원본의 `app.js`, `styles.css` 등은 새 구조로 대체하고 삭제한다(코스 데이터·문구는 옮겨 온다). 원본 상태는 git 기록과 `v1` 태그로 남긴다.

## 3. 데이터 파이프라인 (`pipeline/`)

### 3.1 도시 설정
`config/cities.yaml`에 도시별로 다음을 적는다.
- `id`(예: `paris`), 한국어 이름, 나라, 분석 중심 좌표, 반경(기본 3km, 코스 정류장을 모두 포함하도록 자동 확장).
- 코스 목록: 이름, 정류장(이름·좌표), 발표 자료의 현장 평가(휠체어 난이도 1~5, 루트 추천 별점 1~5, 느낀 점 요약).
- 9개 도시: 런던, 파리, 루체른, 베른, 인터라켄, 밀라노, 베네치아, 피렌체, 로마. 코스와 정류장은 원본 `app.js`의 `FALLBACK_COURSES`에서 옮긴다.

### 3.2 수집
- **도로망**: OSMnx로 보행 네트워크(`network_type="walk"`)를 받아온다. 태그 `surface`, `smoothness`, `incline`, `kerb`, `wheelchair`, `highway`, `ramp`, `bridge`, `tunnel`, `width`를 보존한다.
- **편의시설(POI)**: OSM에서 화장실(`amenity=toilets`, `wheelchair` 태그 포함), 엘리베이터(`highway=elevator`), 벤치, 음수대.
- **고도**: Copernicus GLO-30(30m) DEM 타일을 내려받아 캐시한다.
- 원자료는 `pipeline/.cache/`에 저장하고 git에는 올리지 않는다.

### 3.3 경사 계산
- 각 도로 구간(edge)을 따라 10m 간격으로 고도를 샘플링해 **평균 경사·최대 경사(%)**를 구한다.
- `bridge=yes`, `tunnel=yes` 구간은 지형 고도가 실제 노면과 다르므로 DEM 경사를 쓰지 않는다. `incline` 태그가 있으면 그것을 쓰고, 없으면 "경사 정보 없음"으로 처리한다.
- 30m 해상도 한계(짧은 급경사를 놓칠 수 있음)는 방법론 문서에 명시한다.

### 3.4 접근성 점수 모델
구간 점수(0~100) = `100 − Σ (가중치ᵢ × 감점ᵢ)`, 0 미만은 0으로 자른다. 통과 불가 구간은 점수 대신 `blocked=true`.

| 항목 | 감점 규칙 (0~100) |
|---|---|
| 경사 `slope` | 최대 경사 기준. 5% 미만 0 → 5~8.33%(ADA 1:12) 사이 0→50 선형 → 8.33~12% 사이 50→100 선형 → 12% 초과 100 |
| 노면 `surface` | asphalt·concrete·paved 0 / paving_stones 20 / compacted·fine_gravel 40 / sett·cobblestone·unhewn_cobblestone 70 / gravel·unpaved·grass·dirt 90. `smoothness`가 bad 이하면 +20(최대 100) |
| 연석 `kerb` | 횡단 지점 `kerb=raised` 60, `lowered`·`flush` 0, 정보 없음 0 |
| 불확실성 `uncertainty` | 노면 정보 없음 +15, 경사 정보 없음 +15 |
| 통과 불가 | `highway=steps`(단 `ramp=yes` 또는 `wheelchair=yes`이면 제외), `wheelchair=no` |
| 보너스 | `wheelchair=yes`이면 최종 점수 +10 (최대 100) |

- 기본 가중치: slope 1.0, surface 0.8, kerb 0.6, uncertainty 0.3. 웹에서 바꿀 수 있다.
- 각 구간에는 **최종 점수뿐 아니라 항목별 감점 값을 따로 저장**한다. 그래야 웹에서 가중치를 바꿔 다시 계산할 수 있다.
- **데이터 신뢰도(도시 단위)**: 노면 태그가 있는 구간 비율, 경사 계산이 가능한 구간 비율을 길이 기준으로 계산한다.

### 3.5 경로 계산
- 코스마다 정류장을 순서대로 잇는 두 경로를 NetworkX로 계산한다.
  1. **최단 경로**: 비용 = 길이. 통과 불가 구간도 허용(일반 보행자 기준).
  2. **접근성 최적 경로**: 비용 = 길이 × (1 + α × (100 − 점수)/100), α 기본 3. 통과 불가 구간 제외.
- 비교 지표: 총 거리, 추가 거리, 피한 계단 수, 최대 경사, 경사 6% 이상 구간 길이, 자갈길 길이, 경로 평균 점수, 경로 300m 이내 화장실 수.
- 접근성 경로가 존재하지 않으면(계단으로만 연결 등) `reachable=false`와 막힌 지점을 기록한다.

### 3.6 내보내기 (`web/public/data/`)
| 파일 | 내용 |
|---|---|
| `cities.json` | 도시 목록, 중심 좌표, 요약 지표(평균 점수, 신뢰도, POI 밀도, 노면 구성 비율) |
| `{city}/segments.geojson` | 구간 선, 항목별 감점, 점수, blocked, 길이 |
| `{city}/graph.json` | 브라우저 경로 계산용 경량 그래프(노드 좌표 배열 + 간선 목록: from, to, 길이, 감점들, blocked, 구간 id) |
| `{city}/pois.geojson` | 편의시설 점 |
| `{city}/courses.json` | 코스 정보, 현장 평가, 두 경로의 좌표·지표·경사 단면(거리별 고도/경사) |

- 좌표는 소수점 5자리(약 1m)로 줄인다. 도시당 전체 용량 목표: gzip 기준 2MB 이하. 넘으면 반경을 줄이거나 `service`/`footway` 외 불필요 간선을 정리한다.

### 3.7 방법론 노트북
`notebooks/methodology.ipynb`: 데이터 출처 → 전처리 → 점수 공식과 근거(ADA 기준 등) → 도시별 결과 그림 → 한계(OSM 태그 누락, DEM 해상도, 현장 검증 부족). 실행 결과가 포함된 상태로 커밋해 GitHub에서 바로 보이게 한다.

## 4. 웹앱 (`web/`)

### 4.1 기술
Vite + TypeScript(프레임워크 없음), MapLibre GL JS, Observable Plot(차트), Lucide 아이콘(SVG), Pretendard 글꼴, OpenFreeMap 벡터 지도(무료·키 없음). PWA: 매니페스트와 앱 아이콘, 데이터 파일 캐시.

### 4.2 화면 구성 (주소로 바로 열 수 있음)
| 주소 | 화면 | 내용 |
|---|---|---|
| `#/` | 홈 | 유럽 지도에 9개 도시 표시(점수 색), 한 줄 소개, "도시 비교" 진입 |
| `#/{city}` | 도시 | 구간 점수 히트맵 + 편의시설, 하단 시트에 도시 지표와 코스 카드(계산 점수, 현장 평가 배지, 거리, 최대 경사, 피한 계단 수) |
| `#/{city}/{courseIndex}` | 코스 상세 | 최단(회색 점선) vs 접근성(강조색) 경로 겹쳐 보기, 비교 지표 표, 경로 경사 단면 차트, 정류장 목록, 주변 편의시설, "내 조건으로" 패널 |
| `#/{city}/{courseIndex}/nav` | 길안내 | 아래 4.4 참고 |
| `#/compare` | 도시 비교 | 도시별 점수 분포, 노면 구성 누적 막대, ㎢당 편의시설 수, 데이터 신뢰도 |
| `#/about` | 방법론 | 점수 공식, 데이터 출처, 한계, 노트북·GitHub 링크, 원 프로젝트 소개 |

- 모바일: 지도 위 하단 시트(접기/펼치기). 넓은 화면(1024px 이상): 왼쪽 패널 + 오른쪽 지도.
- 상단에 뒤로가기와 현재 위치(도시/코스) 표시. 빈 화면으로 가는 탭은 두지 않는다.

### 4.3 "내 조건으로" (가중치 조절 + 브라우저 경로 재계산)
- 슬라이더 4개(경사, 노면, 연석, 불확실성)와 필수 편의시설 체크(화장실 등).
- 값을 바꾸면 ① 히트맵 색을 다시 계산하고 ② `graph.json`으로 브라우저에서 다익스트라 경로를 다시 찾아 그린다. 기본 경로와 새 경로의 지표 차이를 보여준다.
- 필수 편의시설: 경로 300m 이내에 없으면 경고 문구를 띄운다(경로를 강제로 바꾸지는 않음).
- AI 입력창: 문장을 입력하면 AI가 슬라이더 값을 정해 주고, 이유를 한 줄로 보여준다. 사용자는 그 값을 다시 손으로 고칠 수 있다.

### 4.4 GPS 길안내 (유지, 새로 구현)
- 현재 보고 있는 경로(기본 또는 "내 조건" 경로)를 따라 안내한다.
- 표시: 다음 안내(예: "120m 앞 왼쪽, 경사 7% 구간 시작"), 남은 거리, 다음 정류장, 경로 이탈 경고(경로에서 40m 이상 벗어나면).
- 안내 문구는 경로 좌표의 방향 변화(30° 이상)와 구간 특성 변화(경사·노면·연석)로 만든다. 외부 길찾기 API를 쓰지 않는다.
- **시뮬레이션 모드**: 가상 위치가 경로를 따라 움직이며 안내가 바뀌는 것을 보여준다(속도 조절 1×/4×). 유럽에 있지 않은 사람도 기능을 확인할 수 있다.
- 위치 권한 거부·위치 기능 없음 → 시뮬레이션 모드를 안내한다.

### 4.5 디자인 원칙
- WCAG AA 대비, 터치 영역 44px 이상, 키보드 이동과 화면 낭독기 라벨, `prefers-reduced-motion` 존중, 라이트/다크 모드(원본의 "고대비 모드" 대체).
- 점수 색상은 색각이상에 안전한 순차 색(viridis 계열). 통과 불가 구간은 색 + 점선 패턴으로 구분(색에만 의존하지 않음).
- 이모지 대신 SVG 아이콘. 배경 지도는 채도를 낮춰 분석 레이어가 돋보이게.

### 4.6 코드 구성 (`web/src/`)
`router.ts`, `data/`(불러오기·타입), `scoring.ts`(감점 → 점수), `routing/dijkstra.ts`, `map/`(레이어별), `views/`(화면별), `nav/`(진행 계산·안내 생성·시뮬레이터), `ai/client.ts`, `ui/`(시트·슬라이더 등 공통 부품). 파일 하나가 한 가지 일만 하도록 나눈다.

### 4.7 오류 처리
- 데이터 파일 불러오기 실패 → 해당 화면에 다시 시도 버튼.
- AI 실패(네트워크, 한도 초과) → "지금은 AI를 쓸 수 없어요. 슬라이더로 직접 조절해 보세요."
- 접근성 경로 없음 → 막힌 지점을 지도에 표시하고 설명.

## 5. AI 중계 서버 (`worker/`)

- Cloudflare Worker 하나, 엔드포인트 `POST /weights`.
- 요청: `{ city, text }` (text 300자 이하).
- OpenAI 호출(JSON 스키마 강제 출력). 모델명은 Worker 설정값 `OPENAI_MODEL`로 두고, 기본값은 구조화 출력을 지원하는 저렴한 소형 모델로 한다. 응답 형식:
  `{ weights: {slope, surface, kerb, uncertainty} (각 0~2), required_pois: ["toilet"|"elevator"|"bench"|"fountain"], explanation: string(100자 이하) }`
- Worker가 응답을 다시 검사해 범위를 벗어난 값은 잘라낸다.
- 보호 장치: 허용 Origin은 GitHub Pages 주소와 로컬 개발 주소만, IP당 하루 5회(Cloudflare KV), 본문 크기 제한. OpenAI 키는 Worker 비밀값으로만 보관. OpenAI 대시보드에서 월 사용 상한(예: $5)을 사용자가 설정.
- 웹앱은 Worker 주소를 빌드 설정값으로 받는다. 값이 없으면 AI 입력창을 숨긴다.

## 6. 테스트

- **pipeline (pytest)**: 경사 감점 경계값(5%, 8.33%, 12%), 노면 분류, 통과 불가 판정, 작은 가짜 그래프에서 최단 vs 접근성 경로가 계단을 피하는지, 내보내기 파일 형식.
- **web (Vitest)**: 다익스트라 결과, 가중치 변경 시 점수 재계산, 길안내 진행 계산(가장 가까운 경로 지점, 남은 거리, 이탈 판정), 안내 문구 생성.
- **web (Playwright, 1개)**: 홈 → 파리 → 코스 상세가 열리고 지도와 지표가 보이는지.
- **worker (Vitest)**: 입력 검사, 응답 값 범위 자르기, 한도 초과 처리(OpenAI는 가짜로 대체).

## 7. 배포

- GitHub Actions: push 시 테스트 → `web` 빌드 → GitHub Pages 배포.
- Worker: 사용자가 Cloudflare 계정으로 한 번 `wrangler deploy` 하고 OpenAI 키를 비밀값으로 등록. 단계별 안내를 `worker/README.md`에 쓴다.

## 8. README

한/영 두 언어. 순서: 문제(유럽 휠체어 여행의 어려움, 탐방 배경) → 데이터 → 분석 방법(점수 모델·경로 비교) → 결과(도시 비교 그림, 대표 사례: 베네치아/로마) → 앱 화면(스크린샷, 최단 vs 접근성 비교 GIF) → 한계와 다음 단계 → 실행 방법.
